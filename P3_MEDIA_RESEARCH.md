# P3 media protocol research summary (2026-11-01, subagent, official mirror only where stated)
Source of record: https://openclaw-weixin.newfuture.cc/en/backend-api.html
- getupdates: msgs[].item_list[], MessageItem.type: 1 TEXT, 2 IMAGE, 3 VOICE, 4 FILE, 5 VIDEO.
  ImageItem: media?: CDNMedia, thumb_media?, aeskey?, url?, sizes. VoiceItem: media?, encode_type?, playtime?, text?. FileItem: media?, file_name?, md5?, len?. VideoItem: media?, sizes, thumb_media?.
  CDNMedia: AES-128-ECB, encrypt_query_param?, aes_key? (base64 AES-128 key), encrypt_type?, full_url?.
  Inbound key: per-item key, image_item.aeskey for images, otherwise media.aes_key; precedence/encoding NOT stated in mirror (secondary notes say hex vs raw-base64, unverified).
- Inbound download: mirror gives CDN model but NO explicit download procedure, URL construction, method, or decrypt pseudocode. Use full_url if present, else encrypt_query_param. Secondary (unverified): base https://novac2c.cdn.weixin.qq.com/c2c + /download + encrypt_query_param; AES-128-ECB PKCS7, no IV; key normalised to 16 bytes; some images may be unencrypted; voice SILK may need WAV transcoding. Must live-test before claiming.
- Outbound: POST /ilink/bot/sendmessage (text/image/video/file) and POST /ilink/bot/getuploadurl (CDN upload pre-signed params). Upload-first flow: compute plaintext size/MD5 and ciphertext size after AES-128-ECB; getUploadUrl with no_need_thumb:true; prefer upload_full_url else construct from upload_param; POST ciphertext as application/octet-stream; read x-encrypted-param as encrypt_query_param in CDNMedia reference; send via sendmessage.
  getUploadUrl request: filekey, media_type (1 IMAGE, 2 VIDEO, 3 FILE, 4 VOICE — different numbering from MessageItem.type), to_user_id, rawsize, rawfilemd5, filesize (ciphertext size), no_need_thumb:true, aeskey? (AES-128 key as 32 hex chars). Response: upload_param?, upload_full_url? (precedence), thumb_upload_param? (only if thumb requested).
  sendmessage body is only exemplified for text in mirror; exact image/video/file item JSON, and hex<->base64 key conversion for outbound reference, are NOT stated in mirror (secondary, unverified).
- Size/type limits: NONE found in mirror. Any limit used in P3 must be labelled implementation choice or live-tested, not doc limit.
- Not in doc, do not guess: inbound download URL/method/retry, key precedence/encoding, unencrypted-image case, exact outbound item JSON, filekey generation, encrypt_type values, size/duration/format/quota limits, SILK->WAV, thumbnail rules beyond no_need_thumb:true.
